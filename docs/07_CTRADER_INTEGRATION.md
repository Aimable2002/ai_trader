# 07 — cTrader Integration (Python cBot)

## Purpose
The cBot computes and supplies the context pack and displays signals. It is not the decision-maker and places no trades. It runs on whichever account it is attached to; the system does not care whether that is live or demo.

## Files (`cbot/`)
- `ai_forex_signal.py`: the cBot.
- `AiForexSignal.cs`: parameter stub, generated by `generate_stubs.py` from the backend config so the model dropdown always matches the allowlist.
- `smoke_test.py` + `SmokeTest.cs`: transport check, run this first.

## Parameters (predefined selectors, not free input)
Backend URL, API key, Model (enum), Timeframe 1/2/3 (cTrader TimeFrame selectors). The cBot must be attached to a chart of the smallest selected timeframe and refuses to run otherwise, or if the three timeframes are not distinct.

## Constants (one block at the top of the file)
`CONTEXT_VERSION`, candle count, SMA/EMA/ATR/RSI periods, poll interval. They must match the backend's context version; a test compares them with `config/settings.yaml`. Changing them means releasing a new cBot version.

## Behavior
- `on_bar_closed`: the trigger is the open time of the newest bar. For each timeframe the cBot finds the last bar that is closed at the trigger (by comparing times, so a just-opened higher-timeframe bar is never used), reads exactly 150 closed candles and the indicator values at those indexes, and posts the pack. If any indicator value is missing (not enough loaded history) it sends nothing and prints why.
- `on_timer` polls `/signals/latest` and redraws.
- HTTP calls are synchronous, so the backend replies immediately and the model runs in the background.

## Display
A text panel and horizontal lines for each active signal: entry (green BUY / red SELL) and the zone bounds (grey). The panel shows stale state, status (PENDING/CONFIRMED) and multiple active signals. Rejected and resolved signals disappear.

## The cBot must not
Call model providers, hold provider keys, place or modify orders, show stale data as current, fabricate signals, or send the forming candle.

## Verification status
The pure logic (bar selection, payload, drawing plan, wire format against the backend validator) is covered by tests using a stand-in for the cTrader API. Inside cTrader, verify with `smoke_test.py` first: outbound HTTP, the request body and header APIs, `Timer`, `Chart` drawing calls and the `.cs` stub against your cTrader version. These could not be run outside cTrader.
